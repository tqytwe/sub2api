## Scope

This review is a real Chromium capture of the v0.1.182 implementation worktree. It covers the public bilingual homepage, first-party status page, native documentation route, canonical model catalog route, and the unauthenticated growth entry point. It intentionally records the no-backend behavior separately from production or authenticated acceptance.

## Baseline

The browser was run against `http://127.0.0.1:4173`, with the existing Vite preview serving the current worktree and no process listening on `127.0.0.1:8080`. Every target route returned the HTML shell with HTTP 200. The baseline PNG reference is the approved static production-era board; it is not a claim about current production deployment.

## Prototype

The prototype reference is the existing decoded homepage/status review board. Browser captures below are the actual rendered application, including empty/error states caused by the intentionally absent backend.

## Reuse Decision

The observed pages reuse `PublicContentLayout`, the existing public toolbar/theme switcher, `DocsView`, `ModelPlazaView`, the homepage `HeroSphere`, and the existing status metric geometry. No browser-QA-only component or CSS was introduced.

## State Coverage

- Homepage and English homepage: default public shell, CTA hierarchy, no LMSPEED branding, mobile and desktop layout, reduced-motion branch.
- Status and English status: empty/unavailable metrics (`--`), freshness badge, retry button, explanatory data-watermark copy, and bilingual labels.
- Docs and English docs: native same-origin document cards; no iframe or connection-denied frame was present.
- Catalog and English catalog: unauthenticated loading/error state and login CTA; no horizontal overflow.
- Blindbox: unauthenticated public state only. The capture still contains reward-pool explanatory content, so it must not be read as proof of the authenticated Explorer restriction.

## Viewport Coverage

Normal-light captures cover 360x800, 768x900, 1280x800, and 1600x1000 for home, status, docs, and catalog in both languages. Explicit dark-theme interaction was captured at 360px on the Chinese home, status, and docs. The mobile homepage theme control is inside the expanded menu; selecting dark on docs scrolls the focused control back under the sticky top bar, which is recorded as an interaction follow-up rather than proof of a clean default dark entry state. The catalog error shell did not render the public theme control while the backend was absent. Reduced-motion captures cover home and status in both languages at 360px and 1280px. The initial English-docs capture measured 365px at a 360px viewport; the follow-up after the responsive fix is exactly 360px for both document and body scroll widths, with no out-of-bounds element.

## Evidence

The complete machine-readable record is `docs/visual-reviews/assets/v182-browser-qa/browser-qa-report.json`. It contains route, viewport, language, title, `html[lang]`, dimensions, headings, visible text, console/page errors, failed requests, screenshot paths, and a 53rd follow-up verification record for the English-docs responsive correction. The grouped console errors were limited to expected local-backend failures: `/api/v1/settings/public` returned HTTP 500, producing 184 browser resource-error messages and 60 logged settings-fetch errors across the initial matrix. No unhandled page error was recorded. The follow-up error set contains the same expected settings failure and no page error.

## Residual Risk

The `/en/docs` 360px top-bar overflow is resolved in the local follow-up evidence. Browser captures are local and unauthenticated; they do not replace production Zeabur, CSP/XFO, database migration, or guest/user/admin acceptance. The local Vite process was stopped after follow-up capture; no production settings, SQL, deployment, push, or PR action was performed.
