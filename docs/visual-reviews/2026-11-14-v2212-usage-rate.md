## Scope

Port fixed upstream `v2.21.2@dbed7697a` usage rate cards and request-window pairing to the existing administrator usage page. No new route, billing formula, database object or user-page entry. Source: upstream `7413793f3` and its tag-level default-window fixes. Existing Fork savings and account-cost presentation remain intact.

## Baseline

Inspected current UsageStatsCards and administrator and user UsageViews, the shared Icon, date-picker/filter integration and existing cache-detail tooltip. Before editing the visible component, rendered its actual compiled source with synthetic statistics. Baseline images show four cards; user cards continue to use that layout by default.

## Prototype

Before implementation, saved browser images compiling the existing component with an in-memory fifth-card layout that uses the existing card and text styles. The user-authorized scope is upstream parity on the existing page. Prototype data is synthetic and explicitly labelled; it is development evidence, not a separate application or production result.

## Reuse Decision

Reuse UsageStatsCards, existing card layout, typography, semantic table-number formatting and existing filter requests. At narrow widths retain two columns; at large widths use three, then five on wide screens. No replacement page shell, icon library or new visual pattern. Upstream's separate new-feature badge system is absent here and is not imported just for these metrics.

## State Coverage

Unit tests establish loading as unknown, successful zero as zero, per-minute averages, calendar/instant/default boundaries, and retention of Fork billing totals. View tests establish that each statistics request uses its captured window, and a late old response cannot overwrite either the newer count or window. An unsuccessful refresh preserves the previously paired values under the existing refresh behavior. There are no new buttons, hover-only operations, disabled controls, or focus targets. Existing filter/date-picker interactions remain unchanged. Hint text follows the fixed upstream translation.

## Viewport Coverage

Actual compiled component browser captures cover 360, 768, 1280 and 1920 pixels, both themes and languages, with reduced motion enabled. All 16 combinations for baseline, prototype and updated components have no page overflow or browser errors. Synthetic zero/loading transitions are asserted in the updated browser run. Full authenticated layout and production data remain separate acceptance work.

## Evidence

Assets under `assets/2026-11-14-v2212-usage-rate/` are actual Chromium captures. The temporary build uses only intercepted `https://usage-rate-review.invalid/` assets, without starting an app server or contacting production APIs. Utility/component/view/i18n targeted tests pass: 4 files, 55 tests. Initial RED includes missing utility and missing rate elements; later GREEN verifies functionality. A separate model-sync reviewer checked the time-zone/API boundaries, response/window pairing, failed refresh behavior and preservation of Fork billing; no blocking issue was found in this scope. Observer helpers are not presented as a migrated observer product. Full cumulative checks remain pending integration.

## Residual Risk

The screenshots cover the real shared cards rather than the entire authenticated route. The final cumulative tree still needs typecheck/lint/build, Fork integrity, CI and production administrator browser acceptance. These development captures do not replace that acceptance or prove real payments were executed.
