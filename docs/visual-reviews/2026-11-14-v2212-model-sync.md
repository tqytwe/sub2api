## Scope

Port the fixed v2.21.2 account-type opt-in model refresh into the existing administrator account refresh menu. Preserve Fork OAuth allowlists, group authorization, pricing and manual discovery-only requests. No new user page or navigation.

## Baseline

Read AccountsView, neighbouring UsersView, shared Toggle, floatingPanel and the actual upstream AccountsView before editing. The existing real AccountsView was compiled with synthetic APIs and rendered in a browser. The old menu contained table refresh intervals only and could extend left of the mobile viewport.

## Prototype

Before changing AccountsView, the browser rendered an in-memory extension of the actual existing refresh menu with the upstream OAuth/Token and API Key choices and budget explanation. Prototype images are an initial design iteration, not final screen captures. Updated visual review then found the old absolute menu position unsuitable for the longer mobile menu; the final code uses the upstream fixed floatingPanel positioning already used by the Fork tools menu. No independent visual system was added.

## Reuse Decision

Retain current buttons, Icon, labels, checkboxes, typography, palette and menu styling; reuse the existing getFloatingPanelPosition helper. The administrator explicitly enables each account type; both remain off for existing stored preferences. The existing table refresh switch and interval remain unchanged. This is an extension of the real account page, not a static prototype shipped as a feature.

## State Coverage

Real component tests confirm default opt-out, saved type choices, application API payload/AbortSignal, current-page refresh and cancellation on unmount. Queue tests cover two-worker concurrency, page-change isolation, cancellation, failure cooldown and later shared server cooldown. Existing concurrency-sort regression and locale completeness also pass. The real browser focuses the checkbox and toggles it with Space, verifying checked state and persisted preferences. Loading/modal/menu/hidden states suppress new batches; closing a task, changing filter/page, disabling refresh or switching types cancels the old batch. Successful and skipped counts use a live status paragraph; failures retain existing configuration and consume the cooldown.

## Viewport Coverage

Actual component captures cover 360, 768, 1280 and 1920px, Chinese/English, light/dark and reduced motion. Final capture asserts the API Key checkbox remains visible and within the viewport. The baseline and first prototype intentionally retain the discovered old mobile clipping, so their lack of document horizontal overflow is not described as visual correctness.

## Evidence

Targeted Vitest and backend test commands/results are handed to the integrating thread. Verbose logs and capture harness stay under /data/tmp. Images are actual compiled-component browser captures with synthetic APIs and a simplified surrounding shell. No development server, localhost route or production authenticated browser was used.

## Residual Risk

The final consolidated build, independent review and user-local production acceptance remain required. Synthetic component captures cannot prove live model availability or production permissions. Real model requests and real account policy changes were not performed for screenshots. The unrelated existing timer control can show an unavailable-fixture message in captures because its API is outside this harness; that is not production error evidence.
