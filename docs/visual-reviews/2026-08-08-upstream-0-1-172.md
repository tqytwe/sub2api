- Roles: guest, ordinary user and administrator.
- Languages and themes: Chinese and English in light and dark themes.

## Reuse Decision

- Shared layouts and components reused: existing authentication shell, shared CAPTCHA challenge boundary, OAuth action sections, account and usage tables, Model Plaza table, native form controls, administrator dialogs and localization structure.
- New shared pattern, if any: CAPTCHA providers are coordinated by the shared `CaptchaChallenge` component; no parallel login card, table, dialog or icon system was introduced.
- Design-system exception, if any: Chart.js test palette assertions have a scoped governance comment because they verify chart configuration values rather than introduce UI colors.

## State Coverage

- Default: login, password reset, OAuth launch, account usage, Model Plaza prices and administrator forms retain their existing density and hierarchy.
- Hover and active: existing provider and administrator actions preserve their shared interactive treatment; no unique operation is hover-only.
- Focus-visible and keyboard: form inputs and provider/action controls remain focusable; CAPTCHA is initiated by the user action rather than focus removal or pointer-only state.
- Loading, disabled, empty, error and success: CAPTCHA verification failure or expiry, OAuth pending completion, account quota reset, no usage rows, response-model mismatch and forced-refund confirmation all retain explicit feedback paths.

## Viewport Coverage

- Mobile: 360x800 targets wrapped login/OAuth actions and compact table metadata.
- Tablet: 768x900 targets multi-provider CAPTCHA and administrator controls without compressed labels.
- Desktop: 1280x800 targets dense account, usage, Model Plaza and operations tables.
- Wide or short screen: static board keeps bounded panels; application route widths remain owned by the existing PageFrame and administration layout.
- 200% zoom and reduced motion: added copy wraps inside existing controls, and the merge adds no continuous visual motion.
