## Scope

The administrator gateway-forwarding settings surface gains a separate HTTP 400
encrypted-history recovery switch. The control uses the existing settings form,
shared `Toggle`, feature-notice badge, spacing, semantic tokens, and bilingual
locale scopes.

## Baseline

The existing HTTP 409 recovery control and its surrounding settings layout were
used as the baseline and prototype reference. The new control does not add a
new page shell, card system, icon, or interaction pattern.

## Prototype

`existing-toggle.png` is the captured existing forwarding control used as the
prototype reference before implementation. The scope boundary was limited to
one adjacent independent setting row and its announcement dismissal behavior.

## Reuse Decision

The implementation reuses the admin settings grid, shared `Toggle`, existing
semantic color tokens, `NewFeatureBadge`, and the established locale loading
scopes. No design-system exception was needed.

## State Coverage

The browser capture covers disabled-by-default, enabled, keyboard focus, Chinese
light, English light, English dark, and the per-admin new-feature badge. The
existing settings form tests cover load, save, and independent payload fields.
Loading, save failure, and disabled form states continue to use the parent
settings form behavior.

## Viewport Coverage

The preview asserted no horizontal overflow at 360, 768, 1280, and 1920 pixels.
The 360-pixel capture confirms that the description wraps without colliding with
the switch. Reduced motion was enabled for the captures.

## Evidence

The screenshots in the manifest were generated by the production Vue component
with synthetic state and no external requests. The preview also asserted that
all visible locale keys resolve, that the switch changes via Space, and that the
new-feature badge stays dismissed after reloading the same administrator.

## Residual Risk

The remaining release risk is production administrator acceptance: live save,
reload, permission behavior, and the final deployed build must be checked after
the sync PR is merged and deployed.
