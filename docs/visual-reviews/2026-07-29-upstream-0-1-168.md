## Reuse Decision

- Shared layouts and components reused: existing AppLayout, card, button, input, Icon, Select, PlatformIcon, GroupBadge, LoadingSpinner, semantic color utilities, and locale structure.
- New shared pattern, if any: Model Plaza keeps a dedicated content component so the authenticated embedded route and public standalone route share filtering and table behavior.
- Design-system exception, if any: platform accent raw colors remain centralized in `platformColors.ts` because Model Plaza derives platform tints with CSS `color-mix`; Chart.js payment datasets keep reviewed concrete canvas colors.

## State Coverage

- Default: Model Plaza group sections, pricing table, filter chips, passkey list, payment charts, and admin settings panels were checked structurally.
- Hover and active: broad `transition-all` and decorative gradients were replaced with explicit transitions and semantic surfaces on new model plaza controls.
- Focus-visible and keyboard: existing button/input/shared component focus handling remains in use; the model whitelist checkmark now uses the shared Icon component.
- Loading, disabled, empty, error and success: loading/empty/error states remain explicit; large radii and sustained motion were reduced or reviewed where transient progress indicators remain.

## Viewport Coverage

- Mobile: 360x800 targets available-channel cards, model plaza filters, auth registration, and narrow payment widgets.
- Tablet: responsive grids and wrapped filter controls preserve scan order without fixed route width.
- Desktop: 1280x800 targets administrator workspace density and model pricing table readability.
- Wide or short screen: standalone Model Plaza no longer owns `max-w-7xl`, `mx-auto`, or `min-h-screen`; route framing remains with shared layout responsibilities.
- 200% zoom and reduced motion: reduced-motion risk is bounded by removing persistent animation on new settings controls and documenting transient progress indicators.
