Handoff sequence

The forum starts an OAuth2 authorization code request. The panel holds its session token in JavaScript rather than a cookie, so the backend sees a guest and parks the request on the login page until a session exists.

Step 1 Forum User picks “log in with the platform” on the forum.
Step 2 Backend GET authorize finds no session and redirects to /login carrying the original request URI.
Step 3 Router guard An already-signed-in visitor is no longer bounced to the dashboard.
Step 4 Login Password, passkey or two-factor all satisfy the same watched condition.
Step 5 Forum callback Full page load to the allowlisted forum callback with code and state.

Baseline behaviour

The parameter had no meaning. A signed-in visitor was redirected to the dashboard and a freshly signed-in visitor also landed on the dashboard, so the forum never received its authorization code.

Forum sign-in appears broken with no error shown

Updated behaviour

The pending request survives the guard, is replayed once a session exists, and the browser is handed to the forum. A rejected request clears the parameter, surfaces the existing error toast and falls back to the dashboard.
