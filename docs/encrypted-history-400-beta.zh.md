# HTTP 400 加密历史有损恢复

管理员入口位于**系统设置 → 网关转发行为**，默认关闭，并且与现有的 HTTP
409 恢复开关独立。管理 API 字段为
`openai_400_omit_encrypted_history_enabled`；旧版管理客户端省略该字段时，
后台保留已保存的值。

原生 OpenAI Responses 明确返回加密内容无效的 HTTP 400 后，网关先执行已有
的精确恢复。如果精确恢复无法解决，且管理员开启本开关，最多在同一账号、凭据、
模型和路线上追加一次受限重试；追加重试不能晚于本次原生上游发送的第 3 次。
普通 400、传输失败、WebSocket、HTTP 200 之后的流内错误，以及交付状态不确定
的请求，都不会进入该有损恢复。

有损恢复只处理当前可读任务之前的历史加密内容。支持的可读摘要、文本、工具调用
关系、顺序和数字精度会保留；被省略的加密上下文无法恢复，也不保证能够继续对话。
当前任务密文、压缩状态、服务端会话指针和未知输入结构会直接停止转换，不会静默
改写。

客户端请求和本地历史不会被修改。追加重试可能增加延迟和上游用量；只有确认能够
接受历史上下文丢失时才应开启。

管理员上游错误详情会记录固定枚举诊断，不记录密文、请求正文、凭据或原始推理文本。

## 验证范围

实现包含服务层、handler、管理员设置往返、API 契约、前端和浏览器预览回归。浏览器
预览使用虚构设置状态，不代表生产验收。
