# 玩法福利模块一致性审查报告

> 审查日期：2026-10-06  
> 审查范围：签到、农场(Arena)、盲盒、组队奖励、邀请返利  
> 审查依据：前端展示、后端逻辑、管理后台配置三层对比

## 一、执行摘要

本次审查发现 **10 项关键不一致问题**，涉及：
- **前端展示不完整**：邀请活动阶梯、农场排名机制、盲盒奖励分支未充分说明
- **后台配置缺口**：签到里程碑、Arena 奖励档位、补签规则无管理界面
- **文档与实现脱节**：部分功能有完整逻辑但前端展示简化

**关键结论**：
1. ✅ 后端逻辑与 `docs/GROWTH_PLAY.md` 文档一致，配置来源明确
2. ⚠️ 前端用户页展示过于简化，用户无法获知完整规则
3. ❌ 后台管理缺少关键配置入口，运营只能直接改数据库

## 二、详细不一致问题清单

### 2.1 签到（Check-in）模块

#### 问题 CI-01：连续签到里程碑无后台配置入口
- **前端表现**：`CheckInView.vue:196` 显示连续天数和里程碑奖励提示
- **后端逻辑**：`play_service.go:523` 有完整里程碑计算 `resolveStreakMilestoneBonus(streak, rt.StreakMilestones)`
- **后台配置**：`PlayOpsView.vue` **未提供** `play_checkin_streak_milestones` 配置界面
- **配置来源**：`backend/internal/service/domain_constants.go:564`，数据库 `settings` 表 JSON 格式
- **默认值示例**：
  ```json
  [
    {"days": 7, "bonus": 1.0},
    {"days": 14, "bonus": 2.0},
    {"days": 30, "bonus": 5.0}
  ]
  ```
- **影响范围**：运营无法调整里程碑规则，前端提示与后台管理能力不匹配
- **严重程度**：P1（影响运营效率）

#### 问题 CI-02：补签功能无后台管理入口
- **前端表现**：`CheckInView.vue:37-38` 有 `canMakeup` 逻辑和补签按钮
- **后端逻辑**：`play_service.go` 支持补签，条件为 `can_makeup && redeemable_reward_eligible`
- **后台配置**：`PlayOpsView.vue` **未提供** `play_checkin_makeup_enabled` 开关和补签成本配置
- **配置来源**：`backend/internal/service/domain_constants.go:563`
- **影响范围**：补签功能存在但运营无法管理启停和成本
- **严重程度**：P1（功能已实现但无管理界面）

#### 问题 CI-03：成长能量资格评估规则展示不足
- **前端表现**：`CheckInView.vue:25-26` 只显示"成长能量模式"提示，未说明资格条件
- **后端逻辑**：`docs/GROWTH_PLAY.md:44-52` 明确规定：已验证邮箱、注册≥3天、满足（近7天真实调用 OR 近30天净充值≥¥10 OR 有效订阅）之一
- **后台配置**：`PlayOpsView.vue` **未展示**资格评估规则说明
- **影响范围**：用户和运营都看不到资格判定依据
- **严重程度**：P2（信息透明度问题）

---

### 2.2 农场/竞技场（Arena）模块

#### 问题 AR-01：奖励结算机制说明缺失
- **前端表现**：`PlayHubView.vue:120` 提示"使用 API 即可获得代币"，**未明确说明排名奖励机制**
- **后端逻辑**：`docs/GROWTH_PLAY.md:96-99` 明确："按排行榜结算，倍率只影响展示积分和排名竞争，**不直接倍增奖励金额**"
- **默认奖励档位**：
  - 月榜：Top 1 → $50, Top 3 → $20, Top 10 → $5
  - 日榜：Top 1 → $0.5, Top 3 → $0.2, Top 10 → $0.1
- **后台配置**：`PlayOpsView.vue:62` 有 `ArenaRewardSettings` 组件，但**只显示榜单数据，不提供修改奖励档位的界面**
- **影响范围**：用户可能误以为"农场代币"能直接兑换余额，实际是排名固定金额结算
- **严重程度**：P0（用户预期与实际规则不符）

#### 问题 AR-02：奖励档位无后台配置入口
- **前端表现**：用户页显示"预计奖励"，基于当前排名和固定档位计算
- **后端逻辑**：`play_arena_settlement_rewards`（月榜）、`play_daily_arena_top_rewards`（日榜）控制
- **后台配置**：`ArenaRewardSettings.vue` **只展示榜单，无法修改** Top 1/3/10 奖励金额
- **配置来源**：`backend/internal/service/domain_constants.go:565, 581`
- **影响范围**：运营无法调整激励力度
- **严重程度**：P1（运营管理缺口）

### 2.3 盲盒（Blindbox）模块

#### 问题 BB-01：VIP 分级奖池机制说明不足
- **前端表现**：`BlindboxView.vue:119` 显示 `vipPool`，但**未明确说明不同 VIP 等级使用不同奖池**
- **后端逻辑**：`docs/GROWTH_PLAY.md:88-93`：V0 用 `season-1-v1`，V1-V5 用 `season-1-vip-v1` 到 `v5`，预期回报从 $0.45 逐级到 $0.495
- **后台配置**：`PlayOpsView.vue:63` 有 `BlindboxPoolEditor`，但**未在编辑器中说明 VIP 分级机制**
- **影响范围**：运营可能不知道不同 VIP 用户看到的奖池不同
- **严重程度**：P2（信息透明度问题）

#### 问题 BB-02：成本与每日次数配置入口不明确
- **前端表现**：显示"每日次数"和"成本"
- **后端逻辑**：`play_blindbox_cost`（默认 $0.50）、`play_blindbox_daily_limit`（默认 10）
- **后台配置**：`BlindboxPoolEditor` **可能包含**这些配置，但入口不明确
- **配置来源**：`backend/internal/service/domain_constants.go:551, 553`
- **影响范围**：运营需要确认配置入口
- **严重程度**：P2（待确认）

#### 问题 BB-03：奖励分支说明不足
- **前端表现**：`BlindboxView.vue:131-139` 只强调"余额奖励概率"
- **后端逻辑**：实际按 **优惠券、兑换码、余额** 三路分配（`coupon_weight_bp`, `redeem_code_weight_bp`, `balance_weight_bp`）
- **API 返回**：`/play/blindbox/status` 已返回三路权重，但前端**未充分展示**
- **影响范围**：用户不知道还有优惠券和兑换码分支
- **严重程度**：P0（用户预期偏差）

### 2.5 邀请返利（Affiliate）模块

#### 问题 AF-01：活动规则展示过于简化
- **前端表现**：`PlayHubView.vue:186-192` 只显示活动名称和"关注"徽章
- **后端逻辑**：支持**阶梯奖励、净实付/实际消费双门槛、风控冻结、达标判定**等复杂规则
- **API 返回**：`/api/v1/referral-campaigns/{id}` 已返回完整 `reward_tiers`、`net_payment_threshold_cny`、`consumption_threshold_cny`、`hold_duration_hours`
- **后台配置**：`PlayOpsView.vue:1130` 有 `AdminInviteGrowthOperations` 完整 CRUD，功能齐全
- **影响范围**：用户不知道具体规则（充多少、消费多少、何时解冻、阶梯奖励）
- **严重程度**：P0（核心功能规则不透明）

#### 问题 AF-02：普通返佣规则前端展示缺失
- **前端表现**：用户页**未明确提示**"除活动外还有常规 10% 返佣"
- **后端逻辑**：`affiliate_service.go` 支持常规返佣 + 活动叠加/互斥
- **后台配置**：`PlayOpsView.vue:531-537` 有 `legacyRebatePolicy` 配置（`exclude` / `stack`）
- **影响范围**：邀请人可能不知道有两套返利规则
- **严重程度**：P2（信息完整性）

## 七、风险管理

### 技术风险
- **缓存失效**：Settings 表修改后需确保 `PlayRuntimeSettings` 缓存失效  
  **缓解措施**：后端提供缓存刷新接口，前端保存后自动调用

- **API 兼容性**：前端补充展示需确认 API 已返回完整数据  
  **缓解措施**：先审查 API 响应，不足则补充后端字段

- **测试覆盖**：配置表单需补充单元测试和集成测试  
  **缓解措施**：每个方案补充对应测试用例

### 运营风险
- **规则变更告知**：修复后需通知用户规则说明已更新  
  **缓解措施**：发布系统公告或站内信

- **历史数据解释**：Arena 奖励档位修改不影响已结算周期  
  **缓解措施**：在后台显示"修改仅对未来周期生效"提示
