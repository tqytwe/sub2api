# U03 规格与代码质量复审

范围固定为 v2.19.3 / #587 的模型隔离、孤立标记释放及必要前置链路。对照上游 `quality_model_removal.go` 和 `quality-orphan-isolation-release.md`；模板字段增强、共享题批次和完整优先调度另项处理。源码散列见同目录 `reviewed-source.json`，发布和门禁状态见 README 与关联 PR。

## 规格复审

- 质量运维仍在 `/admin/account-quality`；账号定时测试弹窗引导至同一入口。没有增加导航或改动玩法福利、签到和农场。
- 单模型明确失败只隔离对应映射模型；全部模型明确失败才移除所选分组；未知/缺样本不会自动恢复。重复样本必须全部明确通过；映射共享同一模型时按失败/未知优先。
- 隔离标记独立于原生 cooldown，正常调度覆盖映射、OpenAI 实际出站/compact/sticky 与 Antigravity overages；可信内部复测可绕过质量隔离，不能绕过原生限流。
- 分组恢复保留原 priority、created_at、allowed_models；软删除或手动重绑冲突保留归属。软删除组不能被恢复事务复活。
- 模型释放先预览、明确原因和确认；每次一个，最后一个禁止。只释放本规则标准标记或当前缺失目标；拒绝其他 owner、同 owner 漂移、额外字段、原限制、共享/歧义映射、scope 和运行租约冲突。
- 释放同步收缩真实规则及状态范围，保留其他模型、分组快照、计数和历史；版本与 outbox 同事务。操作后读取规则和预览，再同步当前编辑草稿，保留其他未保存字段；回读失败提示已提交但未确认。

## 代码质量复审

- HTTP 入口属于现有管理员路由，固定审计动作；预览不返回凭据、Extra、原始快照或提示词。确认 fence 涵盖账号完整配置/版本、计划行、state、租约、组成员和关联组删除状态。
- 全程保持 account → plan → state；分组层按 catalog → memberships，与现有删除顺序一致。已用真实 PostgreSQL 先复现逆序死锁，再以原测试验证修复。
- 普通计划/模板写入先锁账号后重读归属，不采用等待锁前的旧 MVCC 判定；测试复现并发新 state 可被旧写入漏看，修复后拒绝。
- 普通账号全量保存只保留数据库当前隔离，创建/复制以及局部/批量 Extra 不接受外部隔离字段；6 个真实持久化场景先失败后通过，防止清除新标记或复活已释放标记。
- 事务写入失败全部回滚；真实 outbox 异常验证规则、state、Extra、组和历史保持。整体恢复/对账暂停规则并推进版本，旧 worker 不能重新应用已释放状态。
- 页面已覆盖原因必填、禁用原因、明确确认、冲突后重取预览不自动重放、成功回读、草稿保留及三类回读异常。组件/i18n 定向 39 项；离线真实组件16场景及交互通过。

本轮发现的账号写入保护、编辑草稿/回读反馈和组删除锁序遗漏均已修复并复审。最终完整门禁、PR CI、生产精确 SHA 和用户本机验收分别记录，不以本复审代替执行结果。
