## Findings retained outside the two fixes

1. **Existing frozen entitlement-ID binding gap.** Specification reviewer rated
   this P1; quality reviewer rated it P2. Both classified it as preexisting,
   outside these two fixes and nonblocking for this bounded change. The legacy
   fingerprint in `backend/internal/service/usage_billing.go` omits
   PackageEntitlementID, and requestledger Prepare/Verify do not compare that ID.
   A failed settlement followed by an internal retry replacing the captured
   entitlement with another valid entitlement for the same user/group can
   mismatch the charged quota and stored link. This is a static path, not a new
   dynamic reproduction. Coordinate a separate fix with P0; do not claim
   arbitrary entitlement substitution is prevented.
2. **Administrator concurrency coverage.** Existing scenarios run reset/revoke
   sequentially. They do not establish every interleaving with Apply, nor
   explicitly test a new private request after real revocation. Static review
   found no lock-order cycle; deterministic concurrent coverage is a follow-up.
3. **Missing command fields and error priority.** Nil/nonpositive IDs are safely
   rejected, but do not have dedicated regression cases. If both fingerprint and
   package ownership conflict, the current order reports fingerprint conflict.
4. **Product boundary.** Synthetic authentication and a thin route adapter do not
   prove full production auth, scheduling, usage-worker assembly or browser
   acceptance. These reviews approve neither merge nor deployment.

Remaining runtime gates and the delivery commit are recorded separately in the
continuation evidence and PR; reviewer PASS does not replace those gates.
