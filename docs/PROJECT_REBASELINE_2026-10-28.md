## 新目标

目标是从真实共同祖先起，逐项核对截至 v2.17.7 的上游功能与当前 Fork，迁移或证明等价所有属于本项目的能力，同时保留 Fork 已有合同。此范围按产品功能和依赖界定，不按“最新 release notes”截断，也不将上游整树直接合并。上游共同祖先至目标 tag 有 2,155 个提交、446 个 first-parent merge、3,809 个路径变化；生产与目标 tag 的直接 `git diff --name-status` 有 7,474 条状态记录，包含双方分叉开发产生的差异，不能直接当成待开发数量。

工作按后端/API、前端交互、数据库/计费、构建部署分工；候选可在隔离 worktree 并行开发，主线程统一做跨域依赖和重复实现审查。所有相关工作进入一个累积生产发布批次；未完成版本差异矩阵、提交前统一检查、合并和部署验证前不标为完成。

不再先做旧账本的独立 B2/B3/B4/B5 开发，再重复做上游同步。每项差异必须先回答：上游 v2.17.7 是否已提供、当前 Fork 是否已有等价实现、是否需要保留 Fork 行为、是否涉及数据库迁移、是否真正需要用户界面。

### 2. 后端与数据库候选

- 优先调度：与现有 priority/eligibility/final admission 接口对齐；硬准入不可被评分覆盖，历史未知不得当惩罚。停止调度需覆盖粘性、后备和 WS 复查。
- 凭证异常历史：保留现有 refresh race、超时、credential-generation 保护；结构化错误分类须用 allowlist 和 mock HTTP 验证，不保存原始凭证/响应，不能仅加迁移而缺少 writer/reader。
- 渠道运维：仅作为管理员运维分类；不得改变渠道路由、价格、group 或历史归属。保留 revision CAS、权限与审计，并区分历史 channel_id 与当前人工归属。
- Jev：仅作为显式管理员 opt-in 的质量判题；配置/请求/低置信度都返回 unknown，不调用普通业务账号，不改变账号健康、计费或自动恢复状态。
- 两份 `309_*.sql` 按完整文件名与 checksum 分别审查。迁移器依据 filename 排序、逐文件 SHA256 校验；不得按数字前缀合并。凭证异常迁移依赖被回滚的 token guard 表，不能单独接入；相关 writer/reader/API 是否进入范围先做明确决定。
- 同名迁移 `226_channel_monitor_quota_mode.sql` 上游和 Fork 字节不同，必须保留已部署 Fork 文件且不能直接覆盖；如证明上游修复必要，使用单独向前迁移并补 schema/checksum 兼容测试。
- 部署前须由数据库工作包只读确认生产 `schema_migrations` 状态、SQL 锁表和执行时长，并提供向前兼容策略；禁止执行 down 或删除历史数据。

本批逐项对齐 v2.17.7 正式功能，并回顾 v2.17.6 的 #572–#575，不静默跳过已确定的候选。渠道运维按全栈集成推进；优先调度须先与 B2 硬准入契约联调；凭证失败展示必须连同安全分类、持久化 writer/reader 和所需运维依赖评审；v2.17.7 的质量运维、滚动 24 小时用量、GPT-6.1 Sol 计费和内容审查用户管理必须逐项核对真实 API 与权限。任何页面只在对应后端 API、迁移和权限合同就绪后接入真实管理员路由，不得用空页面代替功能。

### C. 前端生产界面集成

- 只接入已有后端合同的页面、导航、按钮和状态；先查看当前生产实现和相邻页面，再复用现有组件。
- 上游新增的渠道运维、凭证异常、优先调度、Jev 等页面逐项判断是否属于当前产品范围；没有后端合同或权限合同就不接入口。
- 所有页面必须来自实际构建资源验证：加载、空、错误、禁用、权限、保存/刷新、移动/桌面、浅色/深色和中英文按适用范围检查。
- 禁止为了满足视觉检查制作脱离生产路由、假 API、静态原型或与当前运行资源不一致的截图。普通用户不恢复请求台账入口。

### D. 集成验证与一次发布

- 分别运行定向后端/前端/迁移测试，再运行 `make test`、`make build`、Fork integrity、设计检查和文档检查。
- 规格审查、代码质量审查和前后端数据库交叉审查全部通过后，创建一个目标为 `play/main` 的同步 PR。
- PR 合并后只触发一次生产部署；核对 Zeabur 精确 SHA、健康接口和关键 API，再由用户对本批实际受影响的页面与业务路径做回归验收。此前已完成的生产用户验收不重复列为门槛。
- 生产异常、权限放宽、账务/迁移不一致或部署 SHA 不符时停止批次并 revert 合并提交，不继续叠加新改动。

3. 管理端用量：后端显式 `last24h` 已实现。当前本地候选已接入精确滚动窗口、共享筛选快照、错误请求半开日期边界和清理日历范围保护；DateRangePicker/UsageView 定向测试 26 项、router/i18n/请求台账权限回归 122 项通过；TypeScript、生产构建、针对性 ESLint 通过。仍需 DST 与全批复核。Fork integrity 的设计证据子项要求真实页面截图，当前未通过；不以脱离生产的原型替代，候选未提交或部署。

## 团队分工与主线程检查

- **来源/迁移负责人**：锁定上游 tag、迁移顺序、checksum 和回滚条件。
- **后端负责人**：审查准入、结算、路由、凭证、调度和 API 合约，保留 Fork 定制。
- **前端负责人**：基于当前生产页面接入真实路由/API，覆盖交互、状态、导航和响应式，不做孤立原型。
- **数据库/计费负责人**：核对 schema、迁移、钱包/套餐/订阅数字和生产只读对账，不修改历史数据。
- **集成负责人**：汇总测试、构建、CI、Zeabur、健康和用户验收证据；主线程负责最终合并决定。

负责人未分配前标记为“待分配”，不以提交作者推断负责人。每个内部工作包使用独立会话和 worktree；工作包完成后先交证据，主线程统一检查冲突和重复开发。当前交接不得把应用健康、部署成功、未经认证的 API 拒绝或源代码静态检查代替管理员真实操作和生产数据库审计。
