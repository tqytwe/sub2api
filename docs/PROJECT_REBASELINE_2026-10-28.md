## 当前工作分类

### 1. 请求台账生产闭环（当前优先级 P0）

这是下一批独立工作，不扩大已有台账功能边界，不重新开发已合入的 ledger、routing、identifier、分页或 batch 代码。

工作包按以下顺序执行：

1. **账务未知项核对**：核对旧窗口 4 个仍无逐请求计量证据的 `unknown`，并核对订阅计数器窗口净增量。结论只能是可关联、仍未知或不适用；禁止判定免费、估算损失、历史回填或补扣。
2. **协议覆盖补证**：在真实自然流量中记录可获得的 WS 子轮、异步、Realtime/媒体等样本。没有样本就记录缺口，不发送付费请求凑样本。
3. **管理员台账边界**：以管理员身份验证列表、详情、routing、identifier、分页、batch 和容量边界；以普通用户身份确认入口不可见、直接访问被拒绝；游客只验证公开路由不泄露台账。
4. **数据闭环**：对成功、失败、取消、重试/failover、余额/套餐和订阅引用做 UI → API → 数据库读回对账。现有 201 条一致关联不能外推为全链路 100% 通过。

完成证据必须包含当前生产 SHA、Zeabur 成功部署、健康检查、脱敏窗口范围、管理员/普通用户/游客结果及适用 API/DB 对账。缺一项则状态保持“待生产验收”。

### 2. B2：账号权威读取与最终准入（P1）

当前代码和隔离测试已具备技术证据，状态为“已部署、待生产验收”。先验证停用、删除、分组 allowed models、凭证刷新和最终出站模型，覆盖普通、粘性、复合、Responses、Chat、共享 CC 及适用 WS 入口。列表展示不能代替最终请求准入证据。

B2 完成后才进入 B3。不得引入真实 OAuth/TOTP，不把能力分类器或静态列表当作上游权威读取证明。

### 3. B3：结算恢复与流式用量（P2）

当前 ledger、exact correlation、batch proof、routing/identifier 证据代码已部署，状态为“技术已验证、生产闭环待补”。在 B2 身份和准入证据稳定后，核对 retry/failover、取消、断流、数据库写失败时只结算一次，以及冻结价格、钱包、套餐、附加费和订阅计数器。B3 不新增猜测关联字段，不修改历史迁移，不做补扣。

请求台账生产闭环是 B3 的前置验收批次；B3 不得因已有 schema 或本地测试通过而直接标记完成。

### 4. B4：账号统计与管理员路由 UI（P3）

拆成两个可独立验收的工作：账号累计/成本/TPS 统计，以及管理员请求详情的 routing/identifier 展示。两者都要求 UI → API → DB/读回一致、加载/空/错误/权限状态完整。普通用户台账入口已移除，不恢复旧用户截图或旧用户 API 合同。

### 5. B5：其他能力只做单项评估（P4）

P3-2 transport retry、P3-3 timezone 等已在当前树中的能力先做生产验收；账号运营、账号质量、timing、支持工单、双 OAuth、token guard、BPS/Prism/Astra 等逐项盘点后再立项。被回滚或当前树不存在的功能标记为“过时/重新设计”，不从旧账本直接恢复。移动端、Canvas、自动授权不在本批范围。

## 统一任务门禁

每个工作包使用独立 worktree 和分支，由单独任务会话负责；主线程负责规格审查、代码质量审查、依赖排序和最终合并。业务改动先 RED 测试，再实现和重构；文档或只读核查也必须有范围和证据。

提交前运行适用定向测试、`make test`、`make build`、Fork integrity 和文档检查。PR 目标固定为 `play/main`，使用普通 merge，禁止 rebase/强推。合并后记录 Zeabur 精确部署 SHA、健康状态和用户本地三身份验收；未完成项保留 `pending`，不得用旧证据覆盖新 SHA。

## 回退条件

出现权限放宽、台账/余额/订阅不一致、部署 SHA 不符、健康失败或用户数据泄露时停止后续任务，由主线程审查应用 revert。保留现有迁移和审计证据，不删除数据、不执行 down migration、不清空历史记录。
