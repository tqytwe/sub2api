## 新目标

目标是从真实共同祖先起，逐项核对截至 v2.17.7 的上游功能与当前 Fork，迁移或证明等价所有属于本项目的能力，同时保留 Fork 已有合同。此范围按产品功能和依赖界定，不按“最新 release notes”截断，也不将上游整树直接合并。上游共同祖先至目标 tag 有 2,155 个提交、446 个 first-parent merge、3,809 个路径变化；生产与目标 tag 的直接 `git diff --name-status` 有 7,474 条状态记录，包含双方分叉开发产生的差异，不能直接当成待开发数量。

工作按后端/API、前端交互、数据库/计费、构建部署分工；候选可在隔离 worktree 并行开发，主线程统一做跨域依赖和重复实现审查。所有相关工作进入一个累积生产发布批次；未完成版本差异矩阵、提交前统一检查、合并和部署验证前不标为完成。

不再先做旧账本的独立 B2/B3/B4/B5 开发，再重复做上游同步。每项差异必须先回答：上游 v2.17.7 是否已提供、当前 Fork 是否已有等价实现、是否需要保留 Fork 行为、是否涉及数据库迁移、是否真正需要用户界面。

### 2. 后端与数据库候选

- 优先调度：与现有 priority/eligibility/final admission 接口对齐；硬准入不可被评分覆盖，历史未知不得当惩罚。停止调度需覆盖粘性、后备和 WS 复查。
- 凭证异常历史：保留现有 refresh race、超时、credential-generation 保护；结构化错误分类须用 allowlist 和 mock HTTP 验证，不保存原始凭证/响应，不能仅加迁移而缺少 writer/reader。
- 渠道运维：仅作为管理员运维分类；不得改变渠道路由、价格、group 或历史归属。保留 revision CAS、权限与审计，并区分历史 channel_id 与当前人工归属。
- Jev：仅作为显式管理员 opt-in 的质量判题；配置/请求/低置信度都返回 unknown，不调用普通业务账号，不改变账号健康、计费或自动恢复状态。

## v2.17.7 必须逐项验收的行为

1. 质量运维：账号普通保存不能覆盖或复活隔离状态；凭据错误信息不得泄露上游响应正文；规则归属预览、恢复、删除须保留并发与 ownership/version 防护。
2. GPT-6.1 Sol 计费：核对 272,000 输入 token 阈值、缓存 token 计入、OAuth/Setup Token 在不超过 500,000 时的豁免、最终发送模型判定及自定义区间价优先级。
3. 管理端用量：默认“近 24 小时”是精确 `[now-24h, now)`；筛选/翻页/排序/导出共享应用时间快照；清理只能提交日历日期范围；非 UTC 或不完整聚合桶回查原始日志。
4. 内容审查用户：独立管理员解除禁用需要原因并回读用户状态；不得顺带改白名单、清零计数或解除其他安全限制。

以上是验收合同，不代表代码已迁入。每项在矩阵中记录生产实现、上游差异、Fork 决策、数据库/API/UI 影响、测试证据和剩余缺口后，才可标为通过。

## 团队分工与主线程检查

- **来源/迁移负责人**：锁定上游 tag、迁移顺序、checksum 和回滚条件。
- **后端负责人**：审查准入、结算、路由、凭证、调度和 API 合约，保留 Fork 定制。
- **前端负责人**：基于当前生产页面接入真实路由/API，覆盖交互、状态、导航和响应式，不做孤立原型。
- **数据库/计费负责人**：核对 schema、迁移、钱包/套餐/订阅数字和生产只读对账，不修改历史数据。
- **集成负责人**：汇总测试、构建、CI、Zeabur、健康和用户验收证据；主线程负责最终合并决定。

负责人未分配前标记为“待分配”，不以提交作者推断负责人。每个内部工作包使用独立会话和 worktree；工作包完成后先交证据，主线程统一检查冲突和重复开发。
